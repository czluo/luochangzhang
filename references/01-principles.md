# 01 · 原则真身（materialist-dev · 原则1.1）

> 上游：本 skill `SKILL.md`（索引层）。本册 =「前提 + 三原则」的**唯一真身**（2026-10-21）。
> **行文契约（槽位统一）**：每条原则 = **理论锚（一句，供推理延伸）→ 原则句 → 操作（工程动作）→ 判据（可机械验）→ 反例 / 正例**。
> 标记：🔴 禁止 · ✅ 正例 · ❌ 反例 · ⚠️ 注意。哲学表述为通行转述、非逐字引文。

## §1 总纲与认识路线

> **总纲**：先有物，后有则；则定于物，反过来改造物。结论只能来自对象本身；规则必须能说出它反映的那对矛盾、写明定义域——说不出就是猜，猜就必须标明是猜。
>
> **认识路线（螺旋上升）**：调查对象（§2）→ 加工材料（去粗取精 · 去伪存真 · 由此及彼 · 由表及里）→ 抓主要矛盾（§3）→ 定位真身（§4）→ 上升为规律（§5）→ 回实践检验（以矛盾消解为准）→ 复查次要矛盾 → 条件变化 ⇒ 再调查 · 再认识——循环往复，每一循环进到高一级。
> 🔴 反向路线（从概念或经验推对象）即**主观主义**，无论它自称经验、理性还是「既有规则」（§6）。

## §2 前提：没有调查就没有发言权

- **理论锚**：认识发生于实践之后、以对象为源——未经调查的对象，对它的一切断言都是先验投射。
- **原则句**：🔴 任何结论 / 判断 / 评价 / 口径裁定 / 方案，在下笔或开口之前必须**已经完成调查**；调查未完成 ⇒ 只陈述「待查（下一步查什么）」，不出结论。
- **操作**：
  1. 列「结论依赖的事实清单」，逐条标注证据来源（读到的文件 · 跑过的判据脚本输出 · 日志行）；
  2. 取证手段三选一：读真实产物 / 跑判据脚本 / 看日志；⚠️ 取基线必须**按 `mtime` 取最新产物**——拿旧产物当基线 ⇒ 得出根本不存在的问题，并据此改错地方；
  3. 无证据的条目 ⇒ 写「待查：查 X」；🔴 禁写「大概 / 按经验」。
- **判据**：任何将进入结论的事实，必须来自**可复现的取证**，不得来自推断、记忆或"大概"。
  - 🔴 违例（明文禁止）：「先给个初步看法，之后再核实」·「按经验大概是 X」·「成本高所以保留现状」式**未经取证的论证**——初步看法一旦出口即成他人决策依据，**先发言再补证 = 违例**（不是"效率"）。
  - 🔴 犹豫「要不要核实 / 要不要看一眼」时，答案是查。

## §3 原则① 抓主要矛盾，彻底解决

- **理论锚**：复杂过程由主要矛盾支配，主要矛盾解决后矛盾各方随之转化——改现象不改矛盾，矛盾只转移不消失。
- **原则句**：两案择一，取**解决最彻底**者；🔴 禁把「最小改法 / 权宜之计 / 先这样后面再说」作为推荐项。🔴 现象是矛盾的表现；改现象不改矛盾 ⇒ 矛盾转移，不以消失。
- **操作（两案评估五步）**：
  1. 写**矛盾清单**：这个问题有几对矛盾？哪对是主要的（决定进程）？
  2. 逐案标注：消的是**矛盾本身**还是其**现象**？旧形态是否**同批消失**？维护点增减？
  3. 输出**唯一方案**（🔴 不给「A 最小 / B 彻底」选择题）；
  4. 验收判据写「原矛盾是否消解 / 转化条件是否消除」，🔴 不写「症状是否消失」；
  5. **两点论收尾**：方案落地后复查次要矛盾是否上升为新主要矛盾，🔴 禁「打完就走」——不做转化跟踪 = 下一轮「症状反复」的来源。
- **判据**：
  - **消根因** · **单一真身**（同一概念只有一处定义）· 不留**第二套规则** / **死字段** / **过期契约** / **静默降级路** / 🔴 **向后兼容壳**。
  - 🔴 **禁向后兼容（一改就改彻底）**：「向后兼容 / 存量引用太多 / 先并存等以后再删 / 过渡期」一律**不构成硬理由**——它们是"改不彻底"的伪装，兼容壳本身就是第二套规则（必然漂移、被误读、永久留存）。判定 = **同一次改动内旧形态必须同时消失**（旧字段 / 旧参数 / 旧名 / 旧壳 / 旧编号 / 旧路径 / 旧取值），🔴 禁「新旧并存 + 标 `deprecated` 等下一轮」。
  - **唯一例外 = 外部契约**：跨仓调用方 / 已发布的对外 API / 上游产物**不可同批改** ⇒ 允许并存，但 🔴 必须同批登记「退出条件 + 期限」（无登记的并存 = 永久第二套规则）。🔴 规范 / 文档 / 内部结构**无此例外**（无外部契约可言）。
  - **外部产物判据的移植三件套**（例外条款的操作化 · 缺一不可）：移植**不可同批改**的上游产物判据时，同批须给 ① **指纹基线**（上游原件哈希，变更即 `FAIL`）② **差分对照守卫**（拿上游原件跑同一语料，逐条 100% 等价）③ 退出条件登记。🔴 只抄规则不做 ② ⇒ 漂移不可见 = 静默的第二套规则。
  - **判定对象 = 下游实际消费的那一份**：判定 / 校验依据的数据必须是**消费方真正拿到的那份**；🔴 链路中若发生改写 / 包装 ⇒ 取**改写前 ∪ 改写后**（并集）——只看一端，必漏「另一端形态下才成立」的整类判据。
  - **验证以矛盾消解为准**：症状消失而矛盾未消 = 转移，判不通过。
  - 若仍保留小改法 ⇒ 必须给「不可彻底」的**硬理由**（外部契约不可变 · 上游产物不可改 · **取证证明彻底方案代价更高**）。
  - ⚠️ 彻底 ≠ 破坏面最大：仍须**先取证**证明彻底方案的真实代价（彻底方案常反而零版式变更）。（**扬弃**：彻底消除的是旧**形态**；已验证的行为内核由新形态**完整承接**——承接 ≠ 并存，同批旧形态仍须消失。）
- **反例 / 正例**：❌ 产物重复行 ⇒ 下游加「去重逻辑」兜底（治现象）；✅ 查出「同一语义两处定义」⇒ 合为单一真身，重复自然消失（治矛盾）。

## §4 原则② 找内部联系，定位真身

- **理论锚**：对象性质由内部矛盾决定（内因是根据，外因是条件）；现象是本质的外部表现，本质通过现象可被认识。
- **原则句**：不知道怎么解 / 症状反复时，先问：**这个概念的真身在哪？有几处在定义它？**（问的是内部规定性是否被割裂。）
- **操作（真身定位四步）**：
  1. **grep 定义处**：搜符号名 / 配置键 / 规则文本 ⇒ 列出全部定义点，数「有几处」；
  2. **>1 处 ⇒ 内部规定性被割裂**：本质问题不是症状，而是「同一语义多处定义」⇒ 合并为单一真身，症状自然消失；
  3. **修个例必查同型**：grep 同型调用 / 同构代码，确认无同类隐患；
  4. **修个例必查外因链**：上游契约 · 环境 · 时序 · 数据——内因是变化的根据，外因是变化的条件；根因 = 内因 + 其依赖的外因条件。
- **判据**：
  - 能答出「真身在哪 + **有几处**在定义它」才算定位；🔴 不就局部症状下药——补丁式去重 / 加开关 / 加兜底**都不算解决**。
  - ✅ 正例：产物出现重复行 ⇒ 不修「去重逻辑」，而是查出「同一语义被两处定义」⇒ 合为单一真身后重复自然消失。

**规则 / 阈值 / 边界 / 解析判据的合法性判据**（② 的核心操作）

> 任何**规则 / 阈值 / 边界 / 上限 / 解析判据**，都必须回答：**是什么内部矛盾，使它必然存在？它的定义域是什么？**

| 回答 | 定性 | 处置 |
|---|---|---|
| 状态在此**必然转移**（**度**的关节点）· 契约在此**排他** · 顺序与切分由**机制**决定 | **规律**（推断性） | 按推导式取边界，无需余量；🔴 **必须写明定义域**（成立 / 失效条件） |
| 机制说得出，但**依赖特定条件**（条件在则必然，条件变则未必） | **条件性规律**（相对真理） | 同上写明定义域；🔴 条件变化 ⇒ 重新评估 |
| 实测最大值 × 系数 · 样本跑过没出事 · 试到通过为止 | **现象**（经验性） | **对无知的量化，不是知识** ⇒ 显式标 `假设(经验性)` + 影响面 + **退出条件** + **晋升条件**（找到机制或覆盖充分后升档为规律） |

- 🔴 **禁把现象边界写成普适常量**（把「我看到的」当成「必然如此」）。
- 🔴 **禁跨定义域套用（教条主义）**：规律 / 阈值迁入新场景，先核定义域是否仍成立——成立才可用；不成立 ⇒ 回 §2 重新调查，🔴 禁「历来如此」式套用。
- 🔴 **概率 / 统计只在「多因素且无确定机制可循」时合法**，且须标明是**置信度**而非**机制**；有机制可循却用概率兜 = 回避矛盾，不算求解。
- **验证方式须与假设类型匹配**：推断性验「判据在**定义域**上成立」；经验性只能靠**多点覆盖**降低风险，🔴 不得宣称「已证明」。

## §5 原则③ 从现象上升到规律，一次定义处处生效

- **理论锚**：一次实践给出的是**特殊**，规律是**普遍**；把特殊直接当普遍 = 经验主义。相对真理在实践中接受检验、向绝对真理前进。
- **原则句**：把一次踩坑提炼为**可复用的不变式**，让规则 / 结构**一次定义、处处生效**；🔴 禁把个案细节写进通用规则。
- **操作（踩坑 → 不变式四步）**：
  1. 去个案化：删掉一次性数值 / 事务实例 / 机器专名；
  2. 找共性：问「这坑的本质是哪对矛盾」⇒ 写成不变式 / 判据（不是又一条特例规则）；
  3. 三条判据自检（见下）；
  4. 回实践检验一次：拿真实新场景验证「零新增规则」成立，抽象才算落地。
- **判据（三条，可机械验）**：① 新场景**不需要新增规则**（由既有抽象覆盖）② 维护点**不随规模增长**（如「版本维护点恒为 2」）③ 规则里**不出现一次性数值 / 事务实例 / 机器专名**。
- **反例 / 正例**：
  - ❌ 每个新模块追加一条特例规则；每加一个文件就要改一处清单；把某次实测数值写成阈值。
  - ✅ 把「文档集合」抽象为 `references/*.md` ⇒ 新增册零代码改；把「版本头真身」收敛到一处 ⇒ 维护点不随册数增长。

## §6 三个主观主义变种（都违反本 skill）

| 变种 | 错在哪 | 工程形态 |
|---|---|---|
| **经验主义** | 把**观测到的形态**当成规律 | 阈值 = 实测最大值 × 2；规则 = 当前样本的归纳 |
| **教条主义** | 把**相对真理当绝对真理**，丢掉定义域 | 旧阈值 / 旧规则直接套新场景不核条件；「历来如此」「规范写了」替代调查 |
| **唯理论** | **脱离对象**造自洽体系 | 为抽象而抽象 / 过度归一 / 先定概念再让事实就范 |

> 三者同错：**把主观顺序当成客观顺序**。唯物主义只认一条路：调查对象 → 找矛盾 → 升规律 → 回实践检验。
> ⚠️ §5 的「高度抽象」**不等于脱离实际**——它要求从大量具体中抽出共性（归纳后再回实践检验），不是先有概念再让事实就范。

## §7 机械抽查（一条即可判违例）

> 任取一个常量 / 阈值 / 规则，问三件：**它由什么矛盾必然推出？推导式是什么？定义域（成立 / 失效条件）是什么？**
> 答不出矛盾或推导式 ⇒ 必须是**显式假设**（带影响面 + 退出条件）；否则即违例。
> 答不出定义域 ⇒ 按**跨定义域套用**违例处理（教条主义）。
