# materialist-dev（原则1.1）效果实验方案

> 对象：本仓库的 skill（`SKILL.md` + `references/01-principles.md`）
> 目的：用可量化、可复现的对照实验，回答「装上这个 skill 之后，模型在疑难决策题上的判断是否变好、好多少」
> 日期：2026-10-21 · 状态：已执行（数据见 `data/`，报告见 `report.md` / `report.html`）

---

## 一、要证伪的假设

H0（零假设）：装上 skill 与不装，回答质量无差异。
H1（备择）：装 skill 组的「可机械判定的合规率」高于对照组。

不证「模型更聪明」，只证一件事：**面对同一批决策陷阱，模型的输出是否更符合可判定的决策纪律**。

## 二、变量设计

| 维度 | 设置 | 理由 |
|---|---|---|
| 自变量 | 系统提示是否装载 skill（`baseline` 无 / `treatment` 有） | 唯一差异源；其余提示词逐字相同 |
| 被试 | `deepseek-v4.1-flash`、`glm-5.3-flash` | 跨两族，避免"只对某个模型有效" |
| 场景 | 8 个决策陷阱（下表） | 每场景都埋了"最小改法 / 凭经验 / 打补丁"的引诱 |
| 重复 | 每格 2 次（temperature=0，仍可能因上游采样产生差异） | 观察同组内部稳定性 |
| 规模 | 8 场景 × 2 模型 × 2 组 × 2 次 = **64 条回答** | 单组 32 条，可按判据维度做比例比较 |
| 输出约束 | 400 字内、禁输出推理过程 | 保证判分看得到"结论与判据"，不比谁更长 |

## 三、8 个决策陷阱场景（真身 = `run_experiment.py::SCENARIOS`）

| ID | 场景 | 埋的陷阱 | 主要考察 |
|---|---|---|---|
| S1 | 报表偶发重复行，PM 要求加去重 | 直接加 `dedup_rows()` 兜底 | 定位真身（同一语义几处定义） |
| S2 | 配置 `timeout` 拆两字段，30 处内部引用 | "先保留并标 deprecated，下版本再删" | 禁兼容壳 / 同批改彻底 |
| S3 | OCR 超时值：200 次采样最慢 12.4s | 要"只要一个数" | 阈值三档定性 + 定义域 |
| S4 | Playwright 换 requests：先给个初步看法 | 逼你在未调查前下结论 | 没有调查就没有发言权 |
| S5 | A 改 3 行加开关 / B 重构 200 行 | "时间紧" ⇒ 选最小改法 | 只给一个彻底方案 |
| S6 | 500 行上限沿用新项目，"历来如此" | 跨定义域套用 | 禁教条主义 |
| S7 | 新增数据源要改 5 处清单，漏改两次 | 再加一处集中清单 / 写同步脚本 | 上升为不变式（零新增规则） |
| S8 | bug 修了、测试过了，怎么验收 | 症状消失即通过 | 验收问矛盾是否消解 |

## 四、判据（可机械判定的二值项）

判分只看回答文本本身，5 条二值判据（`pass` / `fail` / `na`）：

| # | 判据 | fail 的典型形态 |
|---|---|---|
| C1 | `investigate` 拒绝无证据下结论 | 直接断言，或"先给初步看法，后面再核实" |
| C2 | `single_plan` 只给一个彻底方案 | 递 A/B 选择题，或推荐"最小改法/权宜方案" |
| C3 | `no_compat` 同批改彻底 | 主张 `deprecated` 并存、过渡期、以后再删 |
| C4 | `mechanism_domain` 阈值/规则给矛盾+推导+定义域 | 直接给数，"按实测最大值×2" |
| C5 | `root_cause` 定位真身 / 抽不变式 | 加去重、加开关、加兜底、逐处同步清单 |

`na` = 该场景不涉及该判据（如 S4 不涉阈值 ⇒ C4=na），统计时只算 `pass`/`fail`。

## 五、评分方式（防"自己判自己"）

- 判分由**另一模型族**执行：`deepseek-v4.1-flash` 的回答交给 `glm-5.3-flash` 判，`glm-5.3-flash` 的回答交给 `deepseek-v4.1-flash` 判；
- 判分输入**不含组别标签**（盲评），只给「场景问题 + 回答 + 判据定义」；
- 判分要求只输出一行 JSON；解析失败重试 3 次，仍失败则丢弃并记数；
- 机械旁证（不参与主结论，用于交叉验证）：输出字数、`A/B/选项` 标记数（递选择题倾向）、兼容词命中数、调查类词命中数、耗时。

## 六、统计与裁决

- 主指标：**判据级合规率** = 该组全部非 `na` 判据中 `pass` 的占比；
- 区间：Wilson 95% 置信区间（小样本比正态近似稳）；
- 分层报告：按判据、按场景、按模型；
- 裁决口径：treatment 主指标高于 baseline **且** 两模型方向一致 ⇒ 认 H1；若只有单模型改善 ⇒ 只认"该模型有效"，不推广。

## 七、执行步骤（可复现）

```bash
# 采集（分片 · 断点续跑 · 每片 16 次调用）：--model 可选任意两个模型，--arm 二选一
python run_experiment.py --stage subject --model deepseek-v4.1-flash --arm baseline
python run_experiment.py --stage subject --model deepseek-v4.1-flash --arm treatment
python run_experiment.py --stage subject --model glm-5.3-flash --arm baseline
python run_experiment.py --stage subject --model glm-5.3-flash --arm treatment

# 盲评（跨族 · 可续跑 · 单批限量避免长任务）与汇总
python run_experiment.py --stage judge --limit 14
python run_experiment.py --stage report
```

产物：`data/raw.jsonl`（原始回答）· `data/judged.jsonl`（判分）· `data/scores.csv`（扁平表）· `data/summary.json`（聚合）。

## 八、偏差控制与已知局限

1. **判分者与被判者是同类模型**：只能做到跨族 + 盲评，不能消除"同代模型共享偏好"的系统性偏差；缓解手段是同时报告机械旁证，两者方向一致才下强结论。
2. **场景是合成的**：8 个陷阱由本仓真实事故抽象而来，但仍是"选择题式"提问，比真实对话更容易触发纪律；对应结论只能外推到"同类疑难决策"，不能外推到日常编码。
3. **temperature=0 不等于确定**：上游仍可能有采样差异，故每格重复 2 次并报告组内一致性。
4. **样本量 64**：判据级样本 32/组（`na` 会再减），Wilson 区间宽度约 ±1x%，故结论按"方向 + 幅度区间"表述，不给单点精确值。
5. **不测成本**：treatment 的系统提示显著更长（skill 真身 ~5k 字符），本次只测"决策质量"，**未测 token 成本与延迟代价**——报告里单列一节说明，不混入结论。
